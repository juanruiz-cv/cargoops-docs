# CargoOps — Internacionalización (I18N)

> Grupo W4 (frontend) · Fuente canónica: `docs/MASTER-SPEC.md` (§16 idioma de contenido), `docs/OPEN-QUESTIONS.md` (OQ-012), `docs/architecture/ADR/ADR-002-Angular.md` (i18n con @angular/localize), `docs/frontend/FRONTEND-ARCHITECTURE.md` (R5, §5.3).
> Fase 0: documentación. Los bloques fenced son ilustrativos; no se genera código de producción.

## 1. Objetivo

Definir la estrategia de internacionalización del frontend de CargoOps: mecanismo (Angular i18n / `@angular/localize`), idioma inicial es-AR con preparación para inglés (OQ-012), reglas de extracción de textos (nada hardcodeado), claves por feature, formatos de fecha/número/moneda específicos del dominio argentino y pluralización. RTL queda fuera del alcance inicial (decisión explícita).

## 2. Contexto

La UI v1 es es-AR (OQ-012/OQ-034 resueltas: build único es-AR sin conmutador runtime; el inglés queda preparado para v1.1). ADR-002 fija `@angular/localize` preparado desde el inicio. El dominio exige formatos propios: fechas de ingreso (`dd/mm/aaaa`), permanencia en días, capacidades por unidad (pallets/toneladas/m³) — MASTER-SPEC §4.3. Los textos visibles son en español es-AR; los identificadores técnicos, en inglés (FRONTEND-ARCHITECTURE R5). MASTER-SPEC §16 establece español profesional/neutral para toda la documentación; la UI operativa usa es-AR.

## 3. Restricciones

- R1: Cero strings visibles hardcodeados en templates/componentes: todo texto pasa por el sistema i18n (regla del grupo; verificable con rule/lint futuro).
- R2: Identificadores, nombres de componentes, claves y mensajes técnicos en inglés; textos visibles en español es-AR (FRONTEND-ARCHITECTURE R5).
- R3: No se traducen valores de dominio: los enums (`STORED`, `SECTOR`...) nunca cambian; los labels visibles sí se traducen (`CargoStatusBadge`). Códigos de carga, patentes y referencias alfanuméricas se muestran tal cual (mono, DESIGN-TOKENS §5.3).
- R4: `@angular/localize` es decisión de ADR-002 (Accepted); las alternativas solo se documentan, no se reabren sin decisión del orquestador.
- R5: RTL fuera de alcance en v1 (sin requisito árabe/hebreo; estrategia solo se revisa si el negocio lo pide).
- R6: Formatos con `Intl`/CLDR es-AR; prohibido construir fechas o números concatenando strings ("día + '/' + mes").

## 5. Decisiones

### 5.1 Mecanismo: @angular/localize (ADR-002)

- Extracción con `ng extract-i18n` → archivos XLF por locale; builds por locale (`--localize`).
- **v1: solo build es-AR** (locale `es-AR`). El archivo `messages.en.xlf` (inglés) se mantiene al día como preparación, sin build activo (OQ-012/OQ-034 resueltas 2026-09-24: build único es-AR en v1).
- Alternativas evaluadas (registro; la decisión ya es ADR-002):
  - **ngx-translate**: runtime con JSON; simple; desventajas: extracción manual, resolver de plurales propio, tipado débil.
  - **Transloco**: runtime potente con loaders; desventajas: dependencia adicional y política de carga runtime innecesaria para un v1 de un solo idioma.
  - **@angular/localize**: oficial del framework, `ng extract-i18n`, ICU nativo, compilación tipada; desventaja: el cambio de idioma en runtime no es instantáneo (modelo build-per-locale).
- **Conmutación en runtime: NO en v1** (es-AR fijo). Si el negocio exige switch es↔en en v1, se evalúa carga dinámica de bundles traducidos o migración a alternativa runtime — **OQ-034 resuelta (2026-09-24): sin conmutador runtime en v1** (es-AR fijo, OQ-012); arquitectura lista para agregarlo en v1.1.

### 5.2 Reglas de extracción de textos (no hardcodear)

- Todo texto visible se declara con `$localize`, directiva `i18n` en templates, o atributos `i18n-title`, `i18n-placeholder`, `i18n-aria-label`.
- **IDs explícitos** con `@@clave` para estabilidad y trazabilidad (un cambio de source string no rompe las traducciones existentes).
- Prohibido: concatenar partes traducibles (`"Total: " + count`); interpolar valores en strings traducidos sin ICU cuando hay plurales; duplicar textos entre features (reutilizar `common.*`).
- Fuera de i18n: strings técnicos (logs, rutas, requestId), valores de dominio (enums), textos de tests.

```html
<!-- Ilustración (no producción): extracción con i18n -->
<label i18n="@@cargas.list.column.code">Código</label>
<button i18n-aria-label="@@cargas.list.exportPdf" aria-label="Exportar PDF">…</button>
<p i18n="@@cargas.list.permanenceDays">
  {permanenceDays, plural, =1 {1 día} other {{{permanenceDays}} días}}
</p>
```

### 5.3 Claves por feature (namespace)

Convención de IDs: `@@<feature>.<seccion>.<elemento>`.

| Namespace | Ámbito |
| --- | --- |
| `auth.*` | login, logout, errores de sesión |
| `shell.*` | sidebar, topbar, búsqueda global, menú de usuario |
| `dashboard.*` | KPIs, resumen de ocupación, actividad reciente |
| `cargas.*` | listado, detalle, registro/edición, timeline, observaciones, distribución (panel, fila residual "En camión" — BR-042) |
| `camiones.*` | listado/registro de camiones |
| `ubicaciones.*` | detalle/creación/edición de ubicaciones, unidad por defecto por tipo, unidad efectiva y override (BR-041) |
| `mapa.*` | toolbar, leyenda, panel, `LocationCard`, estados de ocupación |
| `planos.*` | editor, propiedades, validaciones de layout |
| `historial.*` | filtros, tabla de movimientos |
| `alertas.*` | `AlertCard`, acciones (reconocer / resolver / mover a rezago) |
| `auditoria.*` | tabla, diffs legibles |
| `configuracion.*` | secciones de configuración |
| `usuarios.*` / `roles.*` | gestión de usuarios, roles y permisos |
| `common.*` | botones genéricos (Guardar, Cancelar, Cerrar), estados empty/error, fechas, errores de red |
| `errors.*` | mensajes del envelope API mapeados a texto amigable (código → mensaje, p. ej. `CARGO_TOTAL_REQUIRED` 422 — BR-042) |

```html
<p i18n="@@cargas.distribution.inTruck">En camión: {{inTruckAmount}} {{inTruckUnit}}</p>

<label i18n="@@ubicaciones.unidad.override">override: pallets</label>
```

### 5.4 Formatos de fechas, números y monedas (dominio AR)

- **Fechas**: visible `dd/mm/aaaa` (ingreso, movimientos); con hora `dd/mm/aaaa HH:mm` (historial, auditoría); formato largo legible (`Intl.DateTimeFormat('es-AR', …)`) en tooltips/detalle. Pipes: `esArDate`, `permanenceDays` (`utils/dates/es-ar-formatter`, FRONTEND-ARCHITECTURE §5.3).
- **API**: ISO 8601 UTC; el formato visible es responsabilidad del cliente (pipes/servicios, nunca el modelo).
- **Números** (CLDR es-AR): separador de miles `.` y decimal `,` — p. ej. `1.234,56`; ocupación `12,5 t`; tabular figures (`tnum`) en tablas y KPIs (DESIGN-TOKENS §5.3).
- **Moneda**: el dominio v1 no opera montos; regla preparada `Intl.NumberFormat('es-AR', { style: 'currency', currency: 'ARS' })` → `$ 1.234,56` (aplicar solo cuando el negocio introduzca valores monetarios; no se agrega requisito que no existe).
- **Unidades de capacidad** (`QuantityUnit` / `CapacityType` — MASTER-SPEC §4.3, BR-041): claves `@@units.area` ("m²"), `@@units.cubicMeters` ("m³"), `@@units.pallets` (singular/plural es-AR), `@@units.tons` ("t"), `@@units.percent` ("%"), `@@units.units` ("u"/"unidades" es-AR) y `@@units.unlimited` ("Ilimitado"), con formato de número es-AR. La unidad por defecto por `LocationType` y el override por ubicación se rotulan con `@@ubicaciones.unidad.default` / `@@ubicaciones.unidad.efectiva` / `@@ubicaciones.unidad.override` (ver DESIGN-SYSTEM §5.6); la fila residual usa `@@cargas.distribution.inTruck` (BR-042).
- **Permanencia**: siempre textual + numérica ("34 días"), nunca solo color (SCREENS D-SC-05); plural con ICU (§5.5).
- **Zona horaria del predio** (America/Argentina/Buenos_Aires asumida para display, servidor en UTC): pendiente de confirmar con backend — DP-I18N-03.

### 5.5 Pluralización

- ICU en `$localize`: `{n, plural, =1 {...} other {...}}` para permanencia (1 día / n días), conteos (1 carga / n cargas; 1 alerta / n alertas), toasts.
- Prohibido resolver plurales en TS (`n === 1 ? 'día' : 'días'`): se delega al motor de mensajes.

### 5.6 Idioma de página y accesibilidad

- `<html lang="es-AR">` fijo en v1 (ACCESSIBILITY §5.1: WCAG 3.1.1); en el futuro, con switch de idioma, el atributo se actualiza dinámicamente.
- Títulos de documento i18n por ruta (ROUTING §5.5; SEO.md); anuncios a11y (aria-live) en es-AR.

## 6. Criterios de aceptación

- CA-1: `ng extract-i18n` extrae el 100 % de strings visibles (0 hardcoded detectables en templates).
- CA-2: Build es-AR reproducible; `messages.en.xlf` al día (preparación inglés, sin build activo en v1).
- CA-3: Fechas/números con formato es-AR verificados por tests unitarios de pipes (qa W8).
- CA-4: Plurales ICU en permanencia, conteos y toasts.
- CA-5: Valores de dominio (enums, códigos) idénticos entre locales.

## 8. Riesgos

- R-01: Strings hardcodeados que se cuelan en features → lint/rule en CI (prohibición de string literals visibles en templates) + review.
- R-02: Cambios de mensaje rompen traducciones → IDs explícitos `@@`.
- R-03: Pedido tardío de switch runtime → arquitectura lista (XLF en al día) y DP-I18N-01 con ruta de evaluación conocida.
- R-04: Formatos asumidos mal (fechas UTC vs local) → contrato ISO + función única de parse/format en `utils` (zona horaria: DP-I18N-03).
- R-05: Traducir mensajes del envelope API sin mapeo de códigos → `errors.*` depende del contrato de errores backend (W5).
